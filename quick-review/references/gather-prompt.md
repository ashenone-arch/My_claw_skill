# gather prompt 模板与硬约束

## 一、拆分判断（Step 2 试探后决定）

| 试探结果 | gather 数量 | 拆分方式 |
|---------|------------|---------|
| 一次命中全部关键信息 | 0 个 | 直接进入报告阶段 |
| 命中部分（缺催化剂/时间表） | 1 个 | 补齐缺口维度 |
| 命中少 / 多维度需求 | 2 个（上限） | ①市场观点 ②催化剂/风险/时间表 |

**禁止**：同一主体 + 同一时间窗拆 3 个以上 gather；同一维度换多个 query 遍历式搜索。

## 二、gather prompt 模板

### 模板骨架（每个 gather 使用）

```
检索{标的}（{代码}，{市场}）的{维度}，目标是为"{用户原始问题}"提供证据。

今天是 {current_date}。{时间范围说明，如：事件发布于8月11-12日，重点检索8月以来内容}。

请检索以下内容：
1. {维度内的具体检索项，3-5 项，按优先级排列}
2. ...
3. ...

检索工具要求：
- 每次 search_finance_reports 调用必须传 date_range={档位}（不足时可扩展一档，如 past_week→past_month），report_types 建议用 {按事件类型映射}，query 中包含具体时间表达（如"2026年"、"2026Q2"）
- 可用 websearch / ask_web_question 补充检索 {补充方向}
- 涉及结构化数据（财务/行情）时，先调用 skill(skill="ae:query-finance-data") 获取路由指引，再用 query_finance_data_primary 查询；query_finance_data 仅作兜底。{港股/美股需注明市场}

【硬约束 - 必须遵守】
- 全部检索调用（含 search_finance_reports、websearch、query 类）合计不超过 5 次
- 按上述检索项优先级执行，达到信息目标后立即整理写文件，禁止发散性探索
- 不要再补充"看看还有没有"之类的新方向

请把检索到的关键信息整理为结构化 Markdown，包括：{维度对应的输出清单}
标注每条信息的来源和日期。

保存到文件：{file_path}
```

### 硬约束措辞（必须逐条包含）

1. **检索次数上限**："全部检索调用合计不超过 5 次"
2. **收敛写文件**："达到信息目标后立即整理写文件，禁止发散性探索"
3. **优先级**："按上述检索项优先级执行"
4. **时效性备注**（skill 主流程要求，必附）：

```
【时效性检索备注】
原始指令：{当前原始用户指令原文}
相对时间：{原始指令中的时间词}
推荐 date_range：{档位}
执行要求：search_finance_reports 必须使用推荐 date_range，除非检索工具拒绝；query 文本仍需包含具体时间表达。
```

## 三、report_types 映射（按事件类型）

| 事件类型 | report_types |
|---------|-------------|
| 个股业绩（A股/港股） | `["点评:公司点评", "海外研报:公司研究", "国内研报:公司研究", "资讯"]` |
| 个股业绩（美股/港股双重上市） | `["海外研报:公司研究", "点评:公司点评", "资讯"]` |
| 行业事件/政策/热点 | `["点评:行业点评", "国内研报:行业研究", "资讯", "会议纪要"]` |
| 产品发布/技术事件 | `["点评:公司点评", "资讯", "会议纪要:公司交流"]` |

## 四、常见超时根因与规避（写入 prompt 时对照）

| 根因 | 规避 |
|------|------|
| 检索项过多（>5 项） | 合并同类项，只留高优先级 |
| 每项都换新 query | 同一维度最多 1 次 query，命中即止 |
| 发散性问题（"看看行业影响""对比竞品"） | 只在用户明确要求时加入，且作为最后优先级 |
| 单次调用耗时（10-27 秒/次） | 用次数上限控制总时长，5 次 × 平均 15 秒 + 整理时间 < 5 分钟 |
