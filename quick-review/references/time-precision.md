# 时间精度映射表（quick-review）

## 通用映射

| 用户表述 | 查询精度 | date_range |
|---------|---------|-----------|
| "今天/昨天/过去24小时/最新/盘后/盘中/这两天" | 日级别 | `past_day` |
| "本周/这周/过去一周/最近一周/近一周/一周内" | 周级别 | `past_week` |
| "本月/这个月/过去一个月/近一个月" | 月级别 | `past_month` |
| "最近/近期/最新/近日/这几天"（无明确时间单位） | 季度级别 | `past_quarter`（默认） |
| "本季度/过去一季度/近一季度/近三个月" | 季度级别 | `past_quarter` |
| "过去半年/近半年" | 半年级别 | `past_half_year` |
| "过去一年/近一年/去年" | 年级别 | `past_year` |
| 不涉及时间 | — | `past_year` |

**原则**：用户说了具体时间单位 → 必须用对应精度，禁止扩大范围。召回量由 recall_num 控制，不要用 date_range 扩大。

## 事件型任务特殊规则

quick-review 的典型场景是"事件刚发生"（业绩发布、突发政策、产品发布），按事件发布时间锚定：

| 场景 | 推荐 date_range | 理由 |
|------|----------------|------|
| 事件发布 ≤3 天（券商点评密集期） | `past_week`（不足扩展 `past_month`） | 点评集中在发布后 1-2 周，past_week 覆盖主窗口 |
| 事件发布 1 周 ~ 1 个月 | `past_month` | 覆盖点评 + 后续解读 |
| 事件发布 >1 个月 | 按用户表述正常映射 | 用户说"近期"→ past_quarter，说"上半年"→ past_half_year |
| 用户明确说某季度（如"2026Q2 业绩"） | 以事件发布日为锚取最近档位 | 业绩 8/11 发布、今日 8/13 → `past_week` 或 `past_month` |

**常见错误（必须避免）**：
- ❌ 事件刚发布却传 past_quarter/past_year"求全面"
- ❌ 用户说"今天"却传 past_week
- ❌ query 中不含时间表达（date_range 与 query 时间互为补充）

**强时间窗优先**：用户明确说"最近一周/今天/2026Q2"，即使同时说"全面/系统/深度"，也不得扩大范围。
