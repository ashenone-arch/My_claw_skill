# 公司/行业事件快速点评（quick-review）

## 概述

对单一公司或行业的近期事件做快速点评，输出"事件速览 + 市场观点 + 催化剂/风险 + 时间表 + 综合判断"五段式文字分析。定位介于 ae:quick-research（泛研究）与 equity-deep-research（9 段深度）之间：比泛研究更聚焦事件本身与市场定价，比深度研究更轻量、更快。

**核心原则**：只输出文字（markdown 原生格式），不生成报告文件、不生成图片图表；单次执行控制在 gather 超时窗口内，从设计上杜绝超时。

## 执行铁律

| # | 规则 | 说明 |
|---|------|------|
| 1 | **先探测后分派** | Step 2 必须先用 1 次精准检索验证数据密度，再决定 gather 数量；信息已充分时不派 gather |
| 2 | **单主体不拆 gather** | 同一主体 + 同一时间窗的多个维度合并为 1 个 gather；只有数据源/时间窗确实不同才拆为 2 个（上限 2 个） |
| 3 | **gather 硬约束** | gather prompt 必须内置"检索调用上限 ≤5 次、达到信息目标立即整理写文件、禁止发散性探索" |
| 4 | **并行** | 多 gather 必须在同一条消息中并行发起（不是逐个发） |
| 5 | **纯文字** | 全文只用 markdown 原生格式（文字/表格/列表），禁止生成图片/图表/可视化；不生成 md 报告文件，不调用 canvas |
| 6 | **溯源** | 每条数据标注来源 + 日期；测算/推算必须显式标注"测算"，不得与披露数据混同 |
| 7 | **事件锚定** | 报告围绕"事件本身 + 市场如何定价"展开，不写成泛公司介绍 |

## 时间精度规则

> 完整映射表见 `references/time-precision.md`。原则：用户说了具体时间单位 → 必须用对应精度，禁止扩大范围。

| 用户表述 | date_range |
|---------|-----------|
| "今天/过去24小时" | `past_day` |
| "本周/过去一周" | `past_week` |
| "本月/近一个月" | `past_month` |
| "最近/近期/最新"/"本季度/近三个月" | `past_quarter`（默认） |
| "近半年" | `past_half_year` |
| "近一年/去年" | `past_year` |
| 明确季度/日期（如"2026Q2"） | 以事件发布日为锚，取发布前后最贴近的档位 |

**事件型任务的特殊规则**：事件刚发布（3 天内）→ 券商点评密集期，`past_week` 或 `past_month` 足够覆盖，不要因"全面"而放大范围；事件发布较久 → 按用户表述正常映射。

## 执行步骤

### Step 1：识别对象与事件

- 提取：标的（公司名 + 代码 + 市场）、事件类型（业绩/产品/政策/热点）、时间语境
- 判断任务归属：本 skill 负责"事件点评 + 市场观点 + 展望"；若用户要求的是 9 段深度研究 → 让位 equity-deep-research；泛研究 → ae:quick-research
- 根据时间语境确定 date_range（见上表）

### Step 2：试探检索（先探测后分派，必做）

用 1 次精准 `search_finance_reports` 验证数据密度：
- query 聚焦"标的 + 事件 + 点评/评级/目标价"，report_types 精确到事件对应类型（业绩点评 → `["点评:公司点评","海外研报:公司研究"]`；行业事件 → `["点评:行业点评","国内研报:行业研究"]`），date_range 按 Step 1 确定
- **同一条消息中并行附加 1 次轻量行情校验**：用 `query_finance_data`（或 `get_current_time`）查最新价/涨跌幅/52 周位置/市值——"股价反应"维度不依赖券商报告内的价格快照，独立验证事件前后股价表现
- **召回甄别**：按标题+正文核对关联公司，过滤噪音条目（如晨会摘要误标关联公司），避免机构观点错配
- 评估命中质量，进入分支判断：

| 试探结果 | 处理 |
|---------|------|
| 一次命中全部关键信息（业绩数据 + 主要券商点评 + 股价反应） | **不派 gather**，直接进入 Step 4，把素材整理后传给 make-report |
| 命中部分（如只有点评、缺催化剂/时间表） | 派 1 个 gather 补齐缺口 |
| 命中少或需多维度（观点 + 催化剂 + 行业传导都要） | 派 2 个 gather 并行（①市场观点 ②催化剂/风险/时间表） |

### Step 3：gather 检索（仅在需要时执行）

> 执行前读取 `references/gather-prompt.md` 获取 prompt 模板与硬约束措辞。

- 同一条消息中并行发起所有 gather；每个必须 `save_to_file=True` + 绝对路径 `file_path`（`D:/AlphaClaw/.alphaclaw/tmp/{标的}_{维度}.md`）
- gather prompt 必须包含硬约束（检索上限、收敛写文件、禁止发散）与时效性备注
- gather 返回后**提取实际文件路径**，不要猜测文件名

### Step 4：报告撰写

- 优先 `make-report`（`stream_to_parent=True`，流式输出到桌面端），传 gather 返回的实际文件路径；若未派 gather，把 Step 2 试探检索的素材整理后直接嵌入 prompt
- 报告按 `references/output-guide.md` 的五段式结构撰写
- 报告不保存为 md 文件，流式输出即最终产物

### Step 5：收尾

- 主 agent 输出"延伸思考"（2-3 个跨视角问题）
- 检查数据来源标注完整性；数据盲区明确标注"未检索到"

## 输出规范（纯文字）

- 只输出文字：markdown 原生表格/列表/段落，禁止图片、图表、可视化、ASCII art
- bullet point 优先：一个 bullet 承载一个信息维度，2-3 行内讲清
- 数据标注：数值保留单位与币种（如"89.33 亿元""8.72 美元"）；测算值标注"测算"
- 目标价类信息标注机构 + 日期，并提示滞后风险（"目标价基于发布时点，需以最新股价校验"）

## 陷阱速查表

| 严重度 | 陷阱 | 正确做法 |
|-------|------|---------|
| 🔴 致命 | 单事件任务拆 2 个以上 gather | 单主体单事件最多 2 个；信息集中时 0 个（试探检索直接命中） |
| 🔴 致命 | gather prompt 无检索次数上限 | 必须内置"检索调用 ≤5 次、达目标立即写文件" |
| 🔴 致命 | 并表/一次性因素撑起的"超预期"被当内生增长 | 点评必须剥离一次性因素，计算并标注内生口径（如"剔除并表贡献后约 +1%"，测算） |
| 🔴 致命 | 目标价直接作为估值锚 | 目标价滞后于股价调整时，提示"目标价体系在下修通道，不宜机械外推" |
| 🟡 重要 | 扩大 date_range 求"全面" | 严格按时间精度表，事件刚发布用 past_week/past_month |
| 🟡 重要 | 券商点评集中期仍在多个 query 间发散搜索 | 一次精准检索优先，不足再补，禁止遍历式搜索 |
| 🟡 重要 | 输出"业绩分析"写成泛公司介绍 | 全程锚定事件与市场定价：beat/miss、评级变化、分歧点 |
| 🟡 重要 | 测算值未标注 | 所有推算/测算显式标"测算"，与披露数据分栏 |
| 🟢 注意 | 股价反应缺失 | 事件型点评必须包含事件前后股价表现（涨跌幅、与 52 周区间位置） |
| 🟢 注意 | 同机构同日多篇观点冲突 | 以最新发布且评级方向更保守者为准；无法判断时并存标注两篇，不擅自取其一 |
| 🟢 注意 | 时间表只写财报 | 纳入事件相关的时间节点（季度合约价、产品发布、版权续约、监管窗口等） |
